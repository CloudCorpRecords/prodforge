# notes

A worked MCP server example: generated by `prodforge init mcp-server notes`, then extended with real tools — `ping` plus an in-memory notes store (`add_note`, `list_notes`, `get_note`).

Stack: `mcp-server` (generated by `prodforge init mcp-server notes`).

## What it shows, end to end

1. **Generate:** `prodforge init mcp-server notes` gives you package.json, tsconfig, server.json, src, and a node:test suite — CLI + MCP in one bin.
2. **Extend:** `src/index.ts` adds a `NotesStore` and a pure `handleTool` dispatcher. Everything exported is unit-testable without the SDK; the MCP server itself starts only inside `main()` via dynamic SDK imports, so the test suite needs no install.
3. **Test:** `npm test` runs the suite — ping, notes add/list/get round-trip, validation errors, unknown-tool errors.
4. **Run:** `npm install && npm start` serves the MCP server over stdio; connect any MCP client, or try the CLI path: `npx tsx src/index.ts ping` prints `pong`.
5. **Ship:** mcpaudit + mcpvet on the built server, then npm, registry, and GHCR publishes, then a shipcheck GO from the published package — the same gate `prodforge ship` runs from the repo root.

## Develop

```sh
npm install
npm test
npm run build
npm start
```
